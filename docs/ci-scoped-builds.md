# Scoped PR checks and explicit full qualification

Pull requests run path classification before choosing checks. The classifier receives the full base and head commit IDs, so it can inspect the complete change even when the changed file is a test fixture, a build recipe, or a new path. A Markdown-only change receives whitespace, UTF-8, and Markdown fence checks without installing Rust or running Cargo.

For Rust-relevant changes, the selector reads `cargo metadata --locked --no-deps --format-version 1` and uses only workspace members and local dependency paths reported by that metadata. It maps each changed Rust file, package manifest, or migration to its deepest owning package, then follows the actual reverse dependency edges. Root `Cargo.toml`, `Cargo.lock`, `.cargo/**`, and the pinned Rust toolchain widen the set to all metadata workspace members. Unknown ownership or an ambiguous local edge fails closed rather than choosing a guessed package set.

The Rust PR gate checks formatting and warnings-denied Clippy for selected packages whose Cargo target sources are not under `vendor/`, on both Linux and Windows. Clippy is limited to library and binary targets and does not lint dependencies. Formatting selectors use the Cargo package name because the pinned `cargo fmt` does not accept version-qualified package IDs; Clippy and test selectors retain the metadata package spec. A changed path under `tests/**` also resolves its owning package and runs that package's Cargo integration-test targets; fixture-only changes run those targets without unrelated package formatting or Clippy. JavaScript module edits receive `node --check`, changed Python tooling receives AST parsing, and changed module package manifests receive JSON parsing. The Atlas donor check remains hash- and file-set-based on pull requests and main pushes; vendor snapshots are never added to the formatting set.

PRs and main pushes run scoped package checks; only integration targets whose package has a changed `tests/**` path are run. The scoped Linux and Windows jobs validate one runner-temp Cargo target outside the checkout and pass it explicitly to Clippy and integration tests, so a public CLI or extracted worker edit cannot allocate a checkout-local `target/`. The full native, offline fixture, and optimized release matrix remains available through explicit `workflow_dispatch`, not every product push. That manual full Rust gate derives all owned workspace packages from metadata, formats and runs production Clippy across them, and runs all their test targets, including shared-contract/client tests; packages whose target sources point into the preserved vendor tree are excluded. Its explicit release binaries use the same separately validated full-qualification target, while scoped checks never call that full path. Atlas-only changes go to the hash/file-set integrity gate and do not become guessed Cargo package seeds. `just verify BASE_SHA HEAD_SHA` is the scoped local format/Clippy gate for a clean checkout at the full head SHA; use the explicit package recipes while working on uncommitted changes. `just test-target PACKAGE TARGET` runs one named Rust integration target, and `just verify-full` retains the full local qualification recipe.

A scoped PR or main-push pass is a targeted edit-quality gate, not full product/native/release acceptance. Use the explicit full workflow when the relevant product path is ready for that broader qualification.

The selector is intentionally conservative: changed Cargo/platform configuration widens scope; files outside known package roots fail; tests with no metadata integration target fail rather than being silently skipped. It does not add a package graph, dependency cache policy, or a separate compiler service.
