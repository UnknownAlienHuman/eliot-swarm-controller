# Eliot Swarm Controller: целевая архитектура v2.6

Nov 27, 2026 · @Iurii

Главное в 2.6: проверено, что ничего важного не потеряно. Шесть сверок прочитали старую документацию (около 400 строк возможностей): потерянное без решения возвращено (раздел 11а [↗](../INDEX.md#карта-разделов)), остальное убрано с причиной (раздел 13б [↗](../implementation/decisions.md)), сводка — приложение Г [↗](INVENTORY.md). Добавлены облачные исполнители и удалённый MCP (раздел 10а [↗](../implementation/plugins/cloud-agents.md)): Runtime без процесса, кандидат по OID из ветки провайдера, защита main правилами GitHub, проверка JWT на нашей стороне. Два новых враждебных ревью нашли 87 замечаний, из них 14 серьёзных; все сверены с кодом и закрыты: автоматы переписаны, и check.py теперь читает таблицы прямо из раздела 14 [↗](../INDEX.md#карта-разделов), а не из своего списка. Исправлены три утверждения о Claude Code, которые v2.5 считал ненайденными, и найдено третье запрещённое ребро крейтов. Что изменилось по пунктам — Б.0.

Главное в 2.5: у каждого понятия одно имя и один модуль-владелец, всего 15 сущностей Store (раздел 1а [↗](../implementation/core.md)); у Task 10 состояний вместо 13, всё ожидание не агента — одно состояние held с типом причины; скрипт нашёл в автоматах 2.4 девять необработанных событий, все закрыты, жизненные циклы есть у каждой сущности (раздел 14 [↗](../INDEX.md#карта-разделов)); построен граф сущностей, крейтов и слоёв демона с инвариантом на каждом ребре и правилами CI с храповиком, нынешний код измерен теми же скриптами (раздел 14а [↗](../GRAPH.md), приложение В [↗](../tools/README.md)); 61 утверждение о донорах сверено с исходниками, 5 неверных исправлены (приложение А [↗](DONORS.md)).

В 2.4: первым делом в нынешнем Store появляется одна сущность Task с версией и попытками (Attempt), и она заменяет разнесённую политику задачи (Goal, сгенерированные правила назначения, аудит через switch, решения владельца, привязки задач в Git) сначала на одном сценарии, назначении задач из папки. Приёмка привязана к версии задачи и точному Git-кандидату; смена исполнителя ждёт подтверждённой остановки старого; доставка в харнесс имеет состояние «отправка начата»; ошибки SQLite разобраны по классам; интегратор доказывает результат достижимостью OID, а не трейлером; обещания изоляции сужены до того, что реально держится на каждой ОС. Миграция идёт законченными сценариями, старый владелец удаляется в том же шаге. Сквозные сценарии отказов — раздел 15 [↗](../implementation/scenarios.md), вердикты по ревью и история версий — приложение Б.

### Б.0 Версия 2.6: ничего не потеряно, облако, новая проверка логики

Запрос владельца: проверить, что не теряется ничего важного; изучить старую документацию, документацию харнессов, облачных агентов (Muse, Cloudflare и др.); продумать, как всё работает; не наделать новых ошибок.

Как проверяли:

- Шесть независимых сверок старой документации с v2.5: 398 строк возможностей, из них потерянных 110 и потерянных частично 139 (с повторами между документами). Решения — приложение Г [↗](INVENTORY.md).
- Документация харнессов на 27.11: Claude Code, Codex CLI и app-server, Gemini CLI, Antigravity CLI, OpenCode, ACP.
- Облачные агенты по официальным страницам: Muse и Muse Code, Cloudflare (Tunnel, Access, MCP portals, Agents SDK, Sandbox), Claude Code on the web, Codex cloud, Jules, Copilot coding agent.
- Два враждебных ревью v2.5 вслепую: раздел 14 [↗](../INDEX.md#карта-разделов) и разделы 1–13а. 87 замечаний, 14 серьёзных. Каждое серьёзное сверено с текстом и кодом 541507c4 до принятия.

Что было почти потеряно и возвращено (раздел 11а [↗](../INDEX.md#карта-разделов), приложение Г [↗](INVENTORY.md)): удалённый MCP с проверкой JWT и принципалами (swarm\_run открывал удалённому клиенту весь реестр); команды владельца stop, interrupt, steer, resume и stop, переживающий рестарт; MCP рабочих агентов minimal, запрет нативных субагентов, права по ролям, отказ от автоматического одобрения разрешений; рамки кадра 8 и 1 МиБ; чтение квот вместо удаляемого quota.rs; запрет тихой смены аккаунта и Hold по тексту; ёмкость аккаунта; doctor и закреплённые версии; Muse Code и Antigravity; иерархия дочерних с пределами; пробуждение по ответу, по дочерней и по фоновому процессу; триггеры cron и on\_event; наблюдение сессий; who; регистрация проекта; учёт расхода; хранение и диск; diagnose и why; обновление и откат; Docker; CI watch; чекпоинты ходов.

Серьёзные ошибки v2.5, которые нашли ревью и которые исправлены:

Остальные исправления: kind, review, gate\_wait и pending в строке Task; claim\_ttl и check\_ttl; held(provider) и held(infra); имена состояний доставки (accepted → stored, шесть состояний); id\_conflict вместо exists\_with\_different\_payload; BUSY на COMMIT — откат и повтор, как в коде; ephemeral вне Delivery; id\_expired после окна дедупликации; отказ журнала runtime — ошибка клиенту; монотонные часы; смена харнесса — замена с gen+1; живой Attempt = starting или running; закрытый список видов Gate; правка workflow только через демон с ревизией; команда revision.changed; Stop.signal переименован в reason, добавлены ping, origin и stderr\_tail; правило 10 с явными исключениями; правило 6 без ложного «гейты защищают merge»; ключ GitHub App у отдельной учётной записи; GIT\_CONFIG\_GLOBAL в раннере интегратора на самом деле не пустой — пункт этапа 5; launchd не в первой волне; scheduler назван модулем; число 141 заменено проверяемым 144.

Исправлено по документации харнессов: SessionStart получает source = compact (v2.5 писал «не найдено»); onFailure не действует на Stop, SubagentStop, TaskCompleted, TeammateIdle и асинхронные хуки (v2.5: «исключения не описаны»); network.tlsTerminate в документации назван экспериментальным (v2.5: «слово не найдено»); предел 8 Stop-блокировок в документации не найден, записаны наблюдаемые 4 и 6; ссылки на turn\_processor.rs и inject\_items — пути в репозитории Codex afe555b, а не в нашем (ревью искало их у нас), это теперь сказано явно; inject\_items подтверждён документацией app-server; turn/interrupt Codex завершает ход статусом interrupted; Gemini CLI для бесплатных и Google One заменён Antigravity CLI с 18.06.2026; предел сессии Gemini — model.maxSessionTurns; ACP v2 — Preview с 20.11.2026; маршруты сервера OpenCode — экспериментальные.

Скрипты: scc.py теперь видит use crate::{…} и super:: — цикл демона 32 из 41 модуля (238 рёбер вместо 192), в eliot-core цикл из 4, eliot-plugin из 5, eliot-store из 4 (раньше их не было видно). deps.py читает [target.'cfg'.dependencies] и нашёл третье запрещённое ребро: swarm-desktop → eliot в цели Windows (profile\_vocabulary, register\_harness\_capabilities).

Что осталось гипотезой: всё облачное (ни один продукт не запускался), связка удалённого MCP с claude.ai и Muse Code, адрес обратного вызова Meta, хуки и steer остальных харнессов, Windows и владение Job, сбой питания, изоляция сети вне Linux, пороги детектора, ожидание писателя Store, хуки при ×10 нагрузке, интегратор против настоящего GitHub.
