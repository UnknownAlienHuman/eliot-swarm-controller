# Проверки архитектуры

Python 3.11+; только стандартная библиотека. Все команды ниже выполняются из корня репозитория, читают файлы и не собирают Rust.

```sh
python3 -I docs/swarm/tools/ratchet.py
python3 -I docs/swarm/tools/ratchet.py --baseline /path/to/base-ratchet.toml
python3 -I docs/swarm/tools/deps.py .
python3 -I docs/swarm/tools/scc.py crates/eliot-daemon/src
python3 -I docs/swarm/tools/check.py docs/swarm/implementation/automata.md
```

## Что действительно проверяется

| Инструмент | Проверка | Ограничение |
| --- | --- | --- |
| `deps.py` | Cargo-декларации normal/build/dev, включая target-specific зависимости и `package` aliases, в том числе workspace-inherited | Это граф деклараций workspace, не результат полного разрешения Cargo features/target |
| `scc.py` | Наибольшая найденная SCC модулей верхнего уровня; `crate::`, braced imports и вложенные `super::` | Текстовый анализ части Rust paths, не compiler graph: inline modules, macros, cfg и reexports полностью не разрешаются. Новый меньший цикл или новые рёбра внутри максимального могут не изменить порог |
| `check.py` | Структура пяти автоматов; повторная таблица под тем же заголовком — ошибка. Для Task также сверяются объявленные состояния и каталог событий | У остальных четырёх автоматов события пока задаются самими строками: опечатка не сверяется с producer/reducer. Не доказываются смысл и взаимоисключение guards, liveness или соответствие Rust. «0 проблем» — только результат этих проверок |
| `ratchet.py` | Запускает сканеры, проверяет завершение и ожидаемые сводки; сравнивает метрики с `ratchet.toml` | Ошибка сканера и неполный результат завершают проверку неуспехом. Числа не измеряют сложность функции, число владельцев policy или качество решения |

Пороги уменьшаются после фактического улучшения; поднимать их ради зелёного CI нельзя. `--baseline` дополнительно запрещает новые допускаемые рёбра, увеличение старых SCC-порогов, удаление наблюдаемого каталога и смену пути автомата. CI читает baseline из base SHA PR или предыдущего SHA push через GitHub API; при ошибке чтения проверка не продолжается. Ручной `workflow_dispatch` проверяет текущие пороги без исторического сравнения.

Это защита от случайного ослабления конфигурации. Она не защищает от намеренной правки самого сканера или workflow; изменения этих файлов требуют обычного ревью. Повторный запуск одной проверки не расширяет её покрытие.

## Историческая реконструкция v2.6

`split_v26.py`, `build_index.py`, `build_backlog.py` — экспортёры исходной спецификации, а не сборка живой документации. Они содержат срезы строк архива, старые тексты и исходные отметки бэклога. **Вывод в репозиторий запрещён кодом**: для реконструкции передайте отдельный каталог staging вне checkout. Например:

```sh
python3 -I docs/swarm/tools/split_v26.py docs/swarm/archive/spec-v2.6.md /tmp/swarm-v26-history
python3 -I docs/swarm/tools/build_index.py docs/swarm/archive/spec-v2.6.md /tmp/swarm-v26-history
python3 -I docs/swarm/tools/build_backlog.py docs/swarm/archive/spec-v2.6.md /tmp/swarm-v26-history
```

Живые контракты, INDEX и backlog редактируются напрямую. `coverage.py` проверяет полноту исторического импорта строк v2.6; он не является критерием актуальности документации или готовности реализации. Исходник в `archive/` остаётся историей. Переходы правятся в `implementation/automata.md`, задачи/критерии — в `backlog.md`; остальные блоки ссылаются на них.
