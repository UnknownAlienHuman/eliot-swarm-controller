# Скрипты проверок

> Приложение В v2.6. Скрипты вынесены в исполняемые файлы рядом: [check.py](check.py), [deps.py](deps.py), [scc.py](scc.py). Храповик для CI — [ratchet.py](ratchet.py) с порогами в [ratchet.toml](ratchet.toml). Сборка документации из v2.6 — [split_v26.py](split_v26.py), [build_index.py](build_index.py), [build_backlog.py](build_backlog.py); [coverage.py](coverage.py) проверяет, что каждая строка v2.6 попала в документы.

Запуск:
- `python3 -I check.py ../implementation/automata.md` — автоматы по таблицам (можно и по самому v2.6).
- `python3 -I deps.py <корень репозитория>` — запрещённые рёбра крейтов.
- `python3 -I scc.py <src-dir> [предел]` — самый большой цикл модулей.
- `python3 -I docs/swarm/tools/ratchet.py` из корня репозитория — всё вместе с порогами (так запускает CI).
- Пересборка документов: `python3 -I split_v26.py ../archive/spec-v2.6.md ..`, затем `build_index.py` и `build_backlog.py` с теми же аргументами, затем `coverage.py`. Пересборка затирает ручные правки в собранных файлах: после того как документы начали жить своей жизнью, правьте их напрямую, а скрипты сборки оставьте как историю.

## Приложение В. Скрипты проверок

Три скрипта на Python 3 без внешних библиотек. Читают файлы и ничего не пишут. На этапе 0 переносятся в CI репозитория. Результаты в разделах 14 [↗](../INDEX.md#карта-разделов) и 14а получены ими на коммите 541507c4; в 2.6 scc.py научился видеть use crate::{…} и super::, deps.py — зависимости целевых платформ, поэтому числа выросли: код не изменился, скрипты стали точнее.

### check.py — автоматы

Использование: python3 -I check.py architecture.md. Скрипт читает таблицы «События Task» и «Переходы …» из раздела 14 [↗](../INDEX.md#карта-разделов) этого документа, а не свой список: правка таблицы без правки скрипта проверяется сразу.
