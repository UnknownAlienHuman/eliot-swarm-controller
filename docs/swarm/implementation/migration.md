# Путь из текущего кода: этапы и удаления

> Источник фактов: целевая архитектура v2.6 (27.11.2026). Текст ниже шапки перенесён из неё дословно; «раздел N» и «приложение X» — номера v2.6, ссылка ↗ ведёт туда, где он теперь. Общая суть — [ARCHITECTURE.md](../ARCHITECTURE.md), связи — [GRAPH.md](../GRAPH.md), навигация — [INDEX.md](../INDEX.md).

**Зачем.** Переход с нынешнего кода (репозиторий eliot-swarm-controller, срез 541507c4) на целевую архитектуру без второго big-bang. Каждый этап — вертикальный срез: заменяет одну старую функцию целиком, переносит вызывающих и в том же этапе удаляет старый путь.

**Владеет.** Порядок этапов 0–12, что удаляется на каждом, критерии приёмки; решение по сохраняемым, отложенным и исключённым функциям.

**Инварианты.**
- Старое не удаляется раньше, чем появилась и подключена замена.
- После каждого среза меряем чистую разницу строк и число старых путей без вызывающих; процента «удаляемого кода» нет.
- Каждый срез уменьшает хотя бы одно число храповика ([GRAPH.md](../GRAPH.md)) или не трогает его.
- Canonical JSON, sha256 команд, квитанции источников и events.put с commit-before-ack не удаляются: это граница эффекта.

**Зависит от.** Все файлы implementation/; граф и храповик — [GRAPH.md](../GRAPH.md); что проверено — [STATUS.md](../STATUS.md).

## 12. Путь из текущего кода и что удаляется

Каждый этап — вертикальный срез: он заменяет одну старую функцию целиком, переносит её вызывающих и сразу удаляет старый путь. Старое не удаляется раньше, чем появилась и подключена замена: в 2.3 этап 2 вырезал owner inbox, settle и canonical JSON до того, как этапы 3–7 добавляли то, что их заменяет, и сборка между ними стояла бы без функции. Первый срез — назначение по папке (раздел 5 [↗](task-controller.md)): там политика задачи сейчас размазана сильнее всего.

Процент удаляемого кода из 2.3 (около 65%) снят: он посчитан по строкам, а не по функциям, и не учитывал, что часть «удаляемого» — граница эффекта (квитанции источников, семантический digest, публикация с чтением remote). Вместо него после каждого среза меряем чистую разницу строк (удалено минус добавлено) и число старых путей, у которых не осталось вызывающих.

Квитанции источников (source\_state) и events.put с commit-before-ack остаются границей эффекта плагина (раздел 10 [↗](plugins/README.md)).

### Что сохраняется, что откладывается, что исключено

| Функция | Решение | Где живёт |
| --- | --- | --- |
| Обычный чат с агентом без Git-задачи | сохраняется | существующий путь сообщений; Task не создаётся |
| Удалённый MCP-клиент (cloud\_mcp.rs) | сохраняется, с проверкой JWT и Grant | этап 11, раздел 10а [↗](plugins/cloud-agents.md) |
| Нативные approval и настройки харнессов | сохраняются | в адаптерах, через согласованные возможности |
| Справедливость между проектами | сохраняется | модуль scheduler в eliot-daemon |
| Экраны Fluent | переносятся на этапе 7 | desktop через реестр |
| Экраны Material | заморожены | удаляются, когда Fluent покрыл их функции |
| Memory API (D-38) | сохраняется вне ядра | внешний сервис |
| Перенос задачи между машинами, несколько демонов, outbox, cache.db | отложено | после конкретного потребителя |
| Контракт B runtime (пережить смерть адаптера) | отложено | после данных о частоте |
| Произвольный движок workflow | исключено из первой волны | workflow.toml настраивает поддерживаемый конвейер |
| Облачный исполнитель | вторая волна | этап 11, раздел 10а [↗](plugins/cloud-agents.md) |
| Плагин deploy | отложено | после первой волны |

Правила и решения, чей эффект не измерен, удаляются на этапе 0. Desktop остаётся клиентом через тот же реестр. Размер: 609 файлов .rs, около 420 тыс. непустых строк, из них около 288 тыс. в crates (пересчитано на 541507c).
