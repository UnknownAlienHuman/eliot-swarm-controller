# Путь из текущего кода: этапы и удаления

> Источник фактов: целевая архитектура v2.6 (27.11.2026). Живой контракт; исходная версия сохранена в archive/spec-v2.6.md; «раздел N» и «приложение X» — номера v2.6, ссылка ↗ ведёт туда, где он теперь. Общая суть — [ARCHITECTURE.md](../ARCHITECTURE.md), связи — [GRAPH.md](../GRAPH.md), навигация — [INDEX.md](../INDEX.md).

**Зачем.** Переход с нынешнего кода (репозиторий eliot-swarm-controller, срез 541507c4) на целевую архитектуру без второго big-bang. Каждый этап — вертикальный срез: заменяет одну старую функцию целиком, переносит вызывающих и в том же этапе удаляет старый путь.

**Владеет.** Границы переноса, источники повторного использования и решения по сохраняемым функциям. Порядок этапов, задачи, критерии и отметки выполнения — только в [backlog.md](../backlog.md).

**Инварианты.**
- Старое не удаляется раньше, чем появилась и подключена замена.
- Приёмка среза — подключённое поведение и удалённые прежние policy-пути; net diff — вспомогательный сигнал, не план удаления строк.
- Храповик ([GRAPH.md](../GRAPH.md)) ограничивает найденные регрессии, но не доказывает упрощение реализации.
- Canonical JSON, sha256 команд, квитанции источников и events.put с commit-before-ack не удаляются: это граница эффекта.

**Зависит от.** Все файлы implementation/; граф и храповик — [GRAPH.md](../GRAPH.md); что проверено — [STATUS.md](../STATUS.md).

## 12. Путь из текущего кода и что удаляется

Каждый этап — вертикальный срез: он заменяет одну старую функцию целиком, переносит её вызывающих и сразу удаляет старый путь. Старое не удаляется раньше, чем появилась и подключена замена: в 2.3 этап 2 вырезал owner inbox, settle и canonical JSON до того, как этапы 3–7 добавляли то, что их заменяет, и сборка между ними стояла бы без функции. Первый срез — назначение по папке (раздел 5 [↗](task-controller.md)): там политика задачи сейчас размазана сильнее всего.

Процент удаляемого кода из 2.3 (около 65%) снят: он посчитан по строкам, а не по функциям, и не учитывал, что часть «удаляемого» — граница эффекта (квитанции источников, семантический digest, публикация с чтением remote). Приёмка смотрит на владельца решения, перенос callers и удаление заменённого пути. Net diff и размер SCC помогают обнаружить регрессию, но не заменяют эту проверку.

Порядок этапов и критерии находятся в [backlog.md](../backlog.md). Эта страница не дублирует их таблицу.

### Первый срез: убрать чтение Claude OAuth, сохранить честную квоту

В `plugins/claude/src/` удаляется связанный путь целиком: `quota.rs`, `lib.rs::mod quota`, обработчик `host.rs` для `quota.read`, регистрация `capabilities.rs::quota_readback` и её callback `external_quota_route`. Последний тоже вызывает `crate::quota::uses_external_route`; удаление только модуля оставляет caller. Общий `eliot_plugin::quota` используется другими харнессами и Claude event parser, он сохраняется.

При отсутствии официального readback capability квота отображается как недоступная/unknown. Не подставлять ноль, не добавлять чтение credentials или скрытый HTTP fallback. Существующий `events.rs::observe_rate_limit_event` остаётся источником полученных ограничений и retry-after; событие ограничения не доказывает полный остаток подписки. Одного `quota_readback = None` недостаточно: `plugin_host/host/discovery.rs::read_quota` сейчас выбирает fallback `quota.read` и всё равно поднимает metadata reader. В этом же срезе общий preflight `Host::quota` возвращает типизированный `unsupported` для явно отсутствующей quota capability до получения reader slot/spawn; действующие readback/retained-capabilities других харнессов сохраняются. `router/catalog.rs::quota_read_error` уже проецирует именно код `unsupported` в корректный ответ; при прямом устаревшем вызове Claude host также возвращает `unsupported`, не выдуманный method-not-found. Проверка сейчас: поиск всех callers, просмотр capability/caller path и минимальный Clippy плагина; реальное отображение квоты до запуска продукта остаётся непроверенным; перестройка routing/cache в эту задачу не входит; исключение — названный preflight существующего вызова.

### Пилот папки: одна граница переключения этапов 2–3

Этап 2 добавляет модель/admission, но сам по себе не включает новую автоматизацию для живого брифа. До переноса один прежний controller владеет assignment key; переключение допустимо, когда Task controller подключает для того же ключа запуск, продолжение, остановку, результат и проверки. Один ключ не обслуживается одновременно Goal-driver и Task controller. Это связный срез этапов 2–3; его можно подготовить несколькими PR, но нельзя активировать наполовину.

Сначала прекращаются прежние policy-переходы именно перенесённого ключа. Общие `assignment_busy`, Goal/audit API и таблицы удаляются только после переноса всех их callers; чужие немигрированные брифы продолжают работать. Контроллер перечитывает Store при старте и потерянном уведомлении, а не выводит состояние из watch. Открытые бюджетные переходы в этапе 3 блокируют включение затронутой ветки поведения: агент не выбирает их смысл сам.

Удаление определяется заменённым поведением и отсутствием callers. Границы эффекта сохраняются до подключения эквивалентной замены; отсутствие замера само по себе не доказывает бесполезность кода. Desktop остаётся клиентом через тот же реестр. Размер: 609 файлов .rs, около 420 тыс. непустых строк, из них около 288 тыс. в crates (пересчитано на 541507c).
