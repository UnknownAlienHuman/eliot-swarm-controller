# Плагин Codex (нативный, app-server, первая волна)

> Источник фактов: целевая архитектура v2.6 (27.11.2026). Текст ниже шапки перенесён из неё дословно; «раздел N» и «приложение X» — номера v2.6, ссылка ↗ ведёт туда, где он теперь. Общая суть — [ARCHITECTURE.md](../../ARCHITECTURE.md), связи — [GRAPH.md](../../GRAPH.md), навигация — [INDEX.md](../../INDEX.md).

**Зачем.** Нативный плагин ради turn/steer (вход в текущий ход), turn/interrupt и thread/inject_items, которых нет в ACP v1.

**Владеет.** JSON-RPC адаптер Codex app-server; turn/start, turn/steer с expectedTurnId, turn/interrupt, thread/resume из ~/.codex/sessions; Stop hook; классы ошибок Codex.

**Инварианты.**
- steer — гонка: на ошибку -32600 «no active turn to steer» доставка переходит на turn/start с тем же сообщением.
- Квотные поля Codex в документации не найдены: Hold только по классу ошибки с retry_after.
- Доверие проекта Codex и готовность песочницы Windows проверяет doctor до первого claim на route; не готово — Hold(auth).
- Пути файлов в описании — в репозитории Codex afe555b, а не в нашем.

**Статус.** Только исходники и документация на 27.11; запуском не проверено (критерии этапов 8–10).

- Codex steer — гонка: ход может закончиться между проверкой и вызовом. На ошибку -32600 доставка переходит на turn/start с тем же сообщением.

Stop hook (Claude Stop, Codex Stop, Gemini AfterAgent, OpenCode idle) не даёт агенту закончить ход, пока есть непрочитанные durable-сообщения, красные проверки или нет записи swarm note за этот ход. Блокировки считает демон, счётчик лежит в Store: 3 блокировки подряд без прогресса — хук отпускает, дальше решает детектор (раздел 5 [↗](../task-controller.md)). На встроенные пределы харнессов не опираемся: у Claude Code счётчик сбрасывается вызовом инструмента (раздел 13а [↗](../../STATUS.md)), у остальных не проверено.

## Вердикт (раздел 10)

Вердикты по харнессам: общий ACP-плагин — базовый путь для всех, кто реализует ACP; нативный плагин Codex — ради turn/steer, turn/interrupt и thread/inject\_items; нативный плагин Claude Code — ради хуков и режима маски секретов на macOS, Linux и WSL2; облачный плагин — задача наружу, результат ветка провайдера, которую интегратор забирает в refs/swarm/cloud/ и сканирует gitleaks до того, как она станет кандидатом (раздел 10а [↗](cloud-agents.md)).

ACP уже реализуют Gemini CLI, OpenCode, Goose, а Claude Code и Codex — через адаптеры. Один ACP-плагин покрывает базовый путь: запуск, промпт, отмена, продолжение сессии. В ACP v1 нет входа в текущий ход, в v2 есть (Preview, объявлен 20.11.2026). Поэтому нативные плагины нужны там, где ACP мало: turn/steer, turn/interrupt и inject\_items в Codex, хуки Claude Code (additionalContext, Stop) и квоты провайдера.

## Компакция (раздел 4)

Компакция — зона харнесса. По документации Claude Code после компакции заново загружает корневой CLAUDE.md и правила без области, правила по путям — по требованию; прежний контекст хуков сжимается, а SessionStart после компакции может добавить свежий (документация хуков: SessionStart получает source = compact). Codex на пути компакции пересобирает начальный контекст с developer\_instructions. Значит, общее «после компакции агент забывает задачу» неверно, но динамические детали задачи могут потеряться. Поэтому swarm hook на SessionStart(compact) отдаёт текущую ревизию task.md и остаток работы; для харнессов без такого события плагин ставит их первым сообщением следующего хода. Своего компактора и переписывания нативной истории нет.

## Права и квоты (раздел 11а)

- Доверие проекта Codex и готовность песочницы Windows проверяет doctor до первого claim на этом route; не готово — route получает Hold(auth) с причиной.

- Hold ставится только по структурированному сигналу: rate\_limit\_event Claude Code, HTTP-статус с retry-after, код ошибки протокола. Квотные поля Codex в документации не найдены, поэтому для Codex Hold только по классу ошибки с retry\_after. Где харнесс отдаёт только текст (Antigravity «Individual quota reached», Muse «API error 429»), текст — подсказка: Stop provider, решает разбор или владелец, автоматического Hold нет.
