# Плагин OpenCode (нативный, первая волна)

> Источник фактов: целевая архитектура v2.6 (27.11.2026). Текст ниже шапки перенесён из неё дословно; «раздел N» и «приложение X» — номера v2.6, ссылка ↗ ведёт туда, где он теперь. Общая суть — [ARCHITECTURE.md](../../ARCHITECTURE.md), связи — [GRAPH.md](../../GRAPH.md), навигация — [INDEX.md](../../INDEX.md).

**Зачем.** OpenCode — HTTP/SSE-сервер с собственной доставкой (steer по умолчанию, иначе queue) и продолжением осиротевших ходов. Нужен адаптер со своими правилами перевода и особым «стопом».

**Владеет.** HTTP-адаптер: POST /api/session/:id/prompt, /interrupt; плагинный хук idle; сессии на сервере.

**Инварианты.**
- «Стоп» для OpenCode — interrupt плюс снятие агента с задачи в Store (новое поколение по трём фактам), после чего swarm hook отвечает пусто, а не только снятие хука.
- Ключ остаётся в файле авторизации харнесса до шлюза подстановки (остаточный риск).

**Статус.** Только исходники; маршруты сервера OpenCode — экспериментальные; поведение при обрыве — по исходникам.

---

| Харнесс | Вход в текущий ход | Не дать закончить | Interrupt | Продолжение сессии |
| --- | --- | --- | --- | --- |

| OpenCode | POST /api/session/:id/prompt, delivery по умолчанию steer, иначе queue (session-inbox.ts:11) | плагинный хук idle продолжает сессию синтетическим входом (packages/core/src/plugin/goal.ts:140) | POST /api/session/:id/interrupt | сессии на сервере; при старте сервер продолжает осиротевшие ходы (packages/core/src/session/execution/restart.ts) |

- По заголовку issue OpenCode, хук idle может продолжать сессию после остановки пользователем (тело не прочитано, не проверено). Поэтому «стоп» для OpenCode — это interrupt плюс снятие агента с задачи в Store (новое поколение по трём фактам, раздел 3 [↗](../daemon.md)), после чего swarm hook отвечает пусто, а не только снятие хука.

Stop hook (Claude Stop, Codex Stop, Gemini AfterAgent, OpenCode idle) не даёт агенту закончить ход, пока есть непрочитанные durable-сообщения, красные проверки или нет записи swarm note за этот ход. Блокировки считает демон, счётчик лежит в Store: 3 блокировки подряд без прогресса — хук отпускает, дальше решает детектор (раздел 5 [↗](../task-controller.md)). На встроенные пределы харнессов не опираемся: у Claude Code счётчик сбрасывается вызовом инструмента (раздел 13а [↗](../../STATUS.md)), у остальных не проверено.

## Секреты (раздел 4)

- Остальные харнессы держат ключ в своём файле авторизации, и это остаётся риском до шлюза подстановки. Шлюз — опция после замера: локальный прокси демона через HTTPS\_PROXY со своим CA подставляет ключ только в заголовок авторизации и только для хоста провайдера и чистит ответы (SecretPolicy::redact\_\*, eliot-core/src/secrets.rs). Прототип показал, что без очистки ответа агент видит ключ, если провайдер его отражает. Работу Codex, OpenCode и Gemini CLI через такой прокси не проверяли. Универсальный TLS-прокси не предпосылка остального переписывания.
