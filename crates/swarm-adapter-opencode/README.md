# `eliot-opencode-v2.rust-http.1` standalone source

This package is intended for `crates/swarm-adapter-opencode` and is independent of the root controller workspace. Its only host dependencies are `swarm-contracts`, `swarm-client`, and `swarm-process` by sibling path. The executable remains disabled/unregistered until an installer supplies an exact executable digest and the Store trusted-catalog route/launch integration is merged.

The exact launch argv is `--config <absolute-path>`. That file contains only `HostConnectionConfig` (`schema_version`, `host_data_dir`, and bounded `IpcConfig`). The owner helper supplies the authenticated binding identity, boot UUID, module descriptor claim, and the protected credential-file path. Descriptor-declared binding config values arrive separately under the seven `ELIOT_SWARM_CONFIG_OPENCODE_*` names documented in the host overlay. The route config must preserve the exact providerID/model/variant and workspace value.

Every dispatched command requires the canonical `input_sha256` supplied by the Store. The journal intent stores `ModuleReceiptIdentity` before any native POST; the receipt is included in the saved outcome. Reconciliation uses `target_input_sha256` only to verify the saved target intent and sends target and reconcile outcomes as separate records. A failed/uncertain POST is never retried. Readback issues GETs only for the saved root/input marker. The adapter never starts, stops, restarts, or kills the OpenCode service and does not bind the native root/scope to the GM incarnation.

The adapter supports only session open, task dispatch, next-turn input, and saved readback reconciliation. It does not implement result page production, agent.result, native hook/MCP completion, Task completion, steering, or broad OpenCode parity. Each host RPC re-authenticates, performs typed `module.hello`, and makes its application call on that same connection because the Store binds the module to the authenticated link ID. Newly emitted target outcomes carry `details.reconcile_operation_id` while preserving the target's own receipt. The journal reloads only its v2 receipt format and remains append-only in this slice, so cumulative storage growth is an explicit unresolved operational gap.

The package was not built or tested in this overlay. Root owns integration, formatting, lock resolution, and remote CI.
